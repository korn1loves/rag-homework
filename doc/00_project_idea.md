# Идея проекта
## Проблема
Большие текстовые датасеты неудобно просматривать вручную: пользователь может не знать, в каком фрагменте содержится нужная информация, и вынужден искать ответ самостоятельно.

Обычная языковая модель может ответить на вопрос без обращения к конкретным источникам, из-за чего появляется риск выдуманных фактов. Для учебного проекта важно показать, как RAG помогает решать эту проблему: сначала система ищет релевантные фрагменты в базе, а затем формирует ответ только на основе найденного контекста.

RAG-подход важно рассматривать не как один промпт, а как цепочку шагов:
данные → чанки → индекс → поиск → ответ с источниками

## Цель проекта
Цель проекта — разработать учебную RAG-систему, которая ищет ответы по текстовым фрагментам из датасета SQuAD 2.0 и показывает пользователю источники найденной информации.
Проект должен пройти полный pipeline: 
ingest → chunking → index → retrieval → demo-answer → UI

В результате пользователь сможет задать вопрос, получить краткий ответ и увидеть, какие фрагменты текста были использованы системой.

## Для кого проект
Проект предназначен для студентов и начинающих специалистов, которые изучают основы RAG и хотят понять, как работает полный цикл построения такой системы.

Система не является production-решением. Это учебный MVP, который показывает основные этапы RAG на понятном и открытом текстовом датасете.

## Какие данные используются
В проекте используется датасет SQuAD 2.0.

SQuAD 2.0 — это открытый датасет для задач question answering. Он содержит текстовые фрагменты из Wikipedia, вопросы к этим фрагментам и ответы. Также в датасете есть вопросы без ответа, что полезно для проверки отказа системы от ответа при недостатке контекста.

В рамках проекта планируется использовать выборку из датасета:
- источник данных: SQuAD 2.0;
- тип данных: текстовые фрагменты Wikipedia, вопросы и ответы;
- язык данных: английский;
- масштаб: 1000+ текстовых записей в `data/raw/datasets.json` или 1000+ чанков после нарезки;
- индексируемое поле: текстовый контекст;
- метаданные: `doc_id`, `title`, `source`, связанные вопросы и ответы.

## Ожидаемый результат MVP
Пользователь открывает Streamlit-приложение, вводит вопрос и получает:
1. найденные релевантные фрагменты текста;
2. score для каждого найденного фрагмента;
3. краткий demo-ответ;
4. список источников, на основе которых сформирован ответ.

Пример вопроса:
> What is the capital of France?

Система должна найти релевантный фрагмент, сформировать ответ и показать источник.

Если вопрос не связан с индексируемыми данными или найденного контекста недостаточно, система должна отказаться от ответа без выдумывания фактов.

Пример negative-вопроса:
> What is the price of the newest iPhone?

Ожидаемое поведение: система сообщает, что в найденных источниках нет достаточной информации для ответа.

## Критерий успеха
Проект считается успешным, если:
1. Репозиторий содержит рабочий RAG-pipeline от исходных данных до Streamlit UI.
2. Данные из SQuAD 2.0 преобразуются в формат `datasets.json`.
3. Тексты нарезаются на чанки и индексируются.
4. Retrieval возвращает top-k релевантных фрагментов со score.
5. Demo-answer формируется только на основе найденных фрагментов.
6. Каждый ответ содержит источники: `doc_id`, score и текстовый фрагмент.
7. Negative-вопрос приводит к корректному отказу без выдуманных фактов.
8. README содержит команды запуска проекта.
9. Тесты проходят успешно через `pytest`.
