# Vision — техническое видение проекта

> Отправная точка для разработки.  
> Идея продукта: [00_project_idea.md](00_project_idea.md)

Учебный RAG на текстовых фрагментах Wikipedia из датасета SQuAD 2.0: локально, просто, с поиском, demo-ответом и источниками.

---

## 1. Технологии

Минимальный стек проекта — только те инструменты, которые нужны для рабочего MVP.

| Слой | Выбор | Комментарий |
|------|-------|-------------|
| Язык | **Python 3.10+** | Основной язык проекта |
| Окружение | **uv** + `.venv` | Управление зависимостями и виртуальным окружением |
| UI | **Streamlit** | Простой интерфейс для вопроса, ответа и источников |
| Retrieval | **TF-IDF + cosine similarity** (`scikit-learn`) | Поиск по текстовым чанкам без тяжелых embedding-моделей |
| Индекс | **Локальные файлы** в `data/index/` | Индекс хранится локально, без отдельной базы данных |
| Demo-answer | **Правила + найденный контекст** | Ответ формируется только по найденным фрагментам |
| Данные | **SQuAD 2.0** → `data/raw/datasets.json` | Текстовые фрагменты Wikipedia, вопросы и ответы |
| Тесты | **pytest** | Проверка chunking, retrieval и источников |
| Зависимости | **`pyproject.toml`** + uv | Установка через `uv sync` |

---

## 2. Данные

В проекте используется датасет **SQuAD 2.0**.

SQuAD 2.0 содержит текстовые фрагменты из Wikipedia, вопросы к этим фрагментам и ответы. Также в датасете есть вопросы без ответа, что полезно для проверки negative-сценариев.

В MVP используется подготовленная выборка:

- источник: SQuAD 2.0;
- язык данных: английский;
- формат исходных данных: `data/raw/datasets.json`;
- масштаб: 1000+ текстовых записей или 1000+ чанков после нарезки;
- индексируемое поле: `text`;
- метаданные: `doc_id`, `title`, `source`, `questions`.

В индекс попадает только текстовый контекст. Вопросы и ответы из датасета можно использовать как метаданные и как основу для demo-проверок.

---

## 3. Формат данных

Исходный файл:

```text
data/raw/datasets.json
```

Ожидаемый формат одной записи:

```json
{
  "id": "squad_000001",
  "title": "Beyonce",
  "text": "Beyonce Giselle Knowles-Carter is an American singer...",
  "source": "SQuAD 2.0 / Wikipedia",
  "questions": [
    {
      "question": "When did Beyonce start becoming popular?",
      "answer": "in the late 1990s"
    }
  ]
}
```

После ingestion данные преобразуются в:

```text
data/processed/documents.jsonl
```

После chunking создается:

```text
data/processed/chunks.jsonl
```

---

## 4. Как строится индекс

Индекс строится отдельным скриптом:

```bash
uv run python scripts/build_index.py
```

Логика построения индекса:

```text
data/raw/datasets.json
→ data/processed/documents.jsonl
→ data/processed/chunks.jsonl
→ TF-IDF vectorizer
→ TF-IDF matrix
→ сохранение индекса в data/index/
```

В `data/index/` сохраняются:

```text
data/index/vectorizer.pkl
data/index/matrix.npz
data/index/chunks.jsonl
```

Назначение файлов:

| Файл | Назначение |
|------|------------|
| `vectorizer.pkl` | Обученный TF-IDF vectorizer |
| `matrix.npz` | Матрица векторов чанков |
| `chunks.jsonl` | Чанки с метаданными и текстом |

Индекс строится офлайн. Streamlit-приложение не должно пересоздавать индекс при каждом запуске.

---

## 5. Как работает поиск

Пользователь задает вопрос в Streamlit UI.

Далее система выполняет retrieval:

```text
вопрос пользователя
→ TF-IDF вектор вопроса
→ сравнение с матрицей чанков через cosine similarity
→ сортировка по score
→ возврат top-k релевантных чанков
```

Каждый найденный результат должен содержать:

- `doc_id`;
- `title`;
- `score`;
- текст чанка;
- источник данных.

Retrieval должен возвращать не только текст, но и метаданные, чтобы пользователь видел, на основании каких источников был сформирован ответ.

## 6. Как формируется demo-ответ

MVP не использует внешнюю LLM. Ответ формируется в demo-режиме на основе найденных чанков.

Правила demo-answer:

1. Ответ строится только по найденному контексту.
2. Если релевантных чанков нет, система отказывается отвечать.
3. Если score найденных чанков слишком низкий, система сообщает, что данных недостаточно.
4. Ответ должен сопровождаться источниками.
5. Нельзя добавлять факты, которых нет в найденных фрагментах.

Пример отказа:

```text
I do not have enough information in the provided sources to answer this question.
```

## 7. Что не используем в MVP

В MVP осознанно не используются:

- OpenAI API;
- внешние LLM;
- LangChain;
- LlamaIndex;
- ChromaDB;
- FAISS;
- sentence-transformers;
- torch;
- reranking;
- hybrid search;
- FastAPI;
- Docker;
- базы данных;
- авторизация пользователей;
- сложная аналитика качества.

Это ограничение нужно для того, чтобы проект оставался учебным и показывал базовую механику RAG без лишней инфраструктуры.

---

## 8. Границы MVP

MVP должен уметь:

1. Читать подготовленный `datasets.json`.
2. Преобразовывать записи в `documents.jsonl`.
3. Нарезать тексты на чанки.
4. Строить TF-IDF индекс.
5. Выполнять top-k retrieval.
6. Формировать demo-ответ по найденным чанкам.
7. Показывать источники в Streamlit UI.
8. Корректно отказываться от ответа при недостатке контекста.
9. Запускаться локально через `uv`.

MVP не обязан:

- отвечать как полноценный ChatGPT;
- понимать сложные перефразировки;
- искать по смыслу через embeddings;
- подключаться к внешним API;
- обновлять индекс автоматически;
- работать как production-сервис.

---

## 9. Как запускать проект

Установка зависимостей:

```bash
uv sync
```

Построение индекса:

```bash
uv run python scripts/build_index.py
```

Запуск Streamlit UI:

```bash
uv run streamlit run app/main.py
```

Запуск тестов:

```bash
uv run pytest tests/ -v
```

---

## 10. Критерий готовности технического MVP

Технический MVP считается готовым, если:

1. `uv sync` выполняется без ошибок.
2. `scripts/build_index.py` создает индекс в `data/index/`.
3. Retrieval возвращает top-k чанков со score.
4. Demo-answer отвечает только по найденному контексту.
5. Streamlit UI показывает вопрос, ответ, найденные чанки и источники.
6. Negative-вопрос приводит к отказу без выдуманных фактов.
7. Тесты проходят успешно через `pytest`.
8. README содержит воспроизводимую инструкцию запуска.
