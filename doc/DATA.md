# DATA — описание данных проекта

## Источник данных

В проекте используется датасет **SQuAD 2.0**.

SQuAD 2.0 — это датасет вопросов и ответов, построенный на основе фрагментов из Wikipedia. В рамках проекта данные используются как учебная база знаний для RAG-pipeline.

Каждая запись содержит текстовый фрагмент, название статьи, источник и связанные с фрагментом вопросы и ответы.

## Масштаб

В текущей версии проекта используется выборка из **1200 записей**.

Файл с исходными данными расположен по пути:

```text
data/raw/datasets.json
```

После этапа ingestion данные преобразуются в формат JSONL:

```text
data/processed/documents.jsonl
```

После этапа chunking создаются фрагменты для поиска:

```text
data/processed/chunks.jsonl
```

После построения индекса создаются файлы:

```text
data/index/vectorizer.pkl
data/index/matrix.npz
data/index/chunks.jsonl
```

## Структура исходных данных

Одна запись в `data/raw/datasets.json` имеет следующий формат:

```json
{
  "id": "squad_00000",
  "title": "Beyoncé",
  "text": "Wikipedia context text...",
  "source": "SQuAD 2.0 / Wikipedia",
  "questions": [
    {
      "question": "When did Beyonce start becoming popular?",
      "answer": "in the late 1990s",
      "is_impossible": false
    }
  ]
}
```

## Что индексируем

Для поиска используется TF-IDF индекс.

В индекс попадают следующие данные:

- `title` — название статьи;
- вопросы из поля `questions`;
- основной текстовый фрагмент из поля `text`.

Такой подход позволяет находить релевантные фрагменты не только по словам из текста, но и по формулировкам вопросов, которые связаны с данным фрагментом.

## Metadata

Для каждого документа и чанка сохраняются metadata.

Используемые поля:

| Поле | Назначение |
|---|---|
| `doc_id` | идентификатор исходного документа |
| `chunk_id` | идентификатор отдельного чанка |
| `title` | название статьи |
| `source` | источник данных |
| `questions` | связанные вопросы и ответы |
| `score` | оценка похожести при retrieval |
| `text` | найденный текстовый фрагмент |

Metadata используется для отображения источников в консольных проверках и Streamlit UI.

## Pipeline обработки данных

Проект использует следующий pipeline:

```text
data/raw/datasets.json
→ scripts/ingest.py
→ data/processed/documents.jsonl
→ app/chunker.py
→ data/processed/chunks.jsonl
→ scripts/build_index.py
→ data/index/vectorizer.pkl
→ data/index/matrix.npz
→ app/retriever.py
→ app/generator.py
→ app/main.py
```

## Ограничения данных

У текущей версии проекта есть несколько ограничений:

- используется ограниченная выборка из SQuAD 2.0, а не весь датасет;
- данные основаны на Wikipedia-фрагментах;
- поиск выполняется через TF-IDF, а не через embedding-модель;
- TF-IDF хуже обрабатывает сложные смысловые переформулировки;
- demo-answer работает только по заранее сохранённым ответам из поля `questions`;
- система не использует внешнюю LLM и не генерирует новый свободный ответ;
- если релевантного контекста недостаточно, система должна отказаться отвечать.

## Использование данных в проекте

Данные используются для демонстрации учебного RAG-подхода:

1. подготовка исходной базы знаний;
2. нарезка текстов на чанки;
3. построение поискового индекса;
4. поиск релевантных фрагментов по вопросу пользователя;
5. формирование ответа с указанием источников;
6. отказ от ответа при недостатке релевантного контекста.

## Проверка

Для проверки документа можно выполнить команду:

```bash
uv run python -c "
from pathlib import Path

p = Path('doc/DATA.md')
assert p.exists(), 'doc/DATA.md не создан'
t = p.read_text(encoding='utf-8')
required = [
    '## Источник данных',
    '## Масштаб',
    '## Что индексируем',
    '## Metadata',
]
for s in required:
    assert s in t, f'нет раздела: {s}'
print('OK: DATA.md')
"
```
